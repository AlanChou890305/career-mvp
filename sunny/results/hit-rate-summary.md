# 命中率結果（10 篇真實語料）

跑法：另開獨立 agent，只給每篇語料的「背景」與「JD」兩段（看不到「實際被問的問題」），用 `../prompt.md` 的 system prompt 各自產生 6-8 題預測。產生完之後，我（已經看過語料真實答案的這個對話）才逐題比對算命中率。完整預測內容見 `../webapp/data.js`（每篇語料的 `predictions` 陣列，含 `hit` 標記）。

**這不是正式盲測。** `docs/validation-plan.md` 要求 30 筆、三人各 10 筆，理想上評分也該由沒設計這版 prompt 的人來做。這裡雖然湊到 10 篇（達到 Sunny 該負責的份額），但命中率判定是我自己主觀認定「語意上算不算對應到」，沒有第二人覆核——結論拿來討論設計方向可以，不能當成「這版 prompt 準不準」的正式答案。

## 看出來的模式（10 篇後更清楚了）

三個原本的假設在 10 篇上大致成立，而且看到一個新的：

1. **對「數據/成果宣稱含糊」型的面試特別準**：#3（Meet.jobs 網路行銷）、#9（UNIQLO 儲備幹部）命中率最高，這兩場面試官問的都是「你剛剛講的東西，我不太信/沒聽懂」型的追問——正好是這版 prompt「成果量化追問」與「JD 缺口追問」的設計核心。

2. **對「標準化技術/知識篩選題」完全測不到**：#1（PayPay 資料科學）、#7（前端工程師）兩篇的真實問題幾乎都是「不管你是誰都會被問」的考古題（過擬合、SQL、closure、CSS 權重），跟候選人背景關聯度低。這類題本來就不是這版 prompt 要抓的目標，但值得記下：**這版 prompt 在技術職位的知識篩選環節幾乎沒有價值**，只在職位越依賴「候選人自己講的故事」時才有用。

3. **背景資訊量太少時，追問只能猜「形式」猜不到「內容」**：#6（社工員）背景只有一句話（應屆畢業生、應徵社福機構），這版 prompt 正確猜到「會有法規/政策類筆試」「會有上機測驗」，但猜錯了測驗的具體內容（猜是系統操作，實際是活動企劃與圖表判讀）。這代表這版 prompt 的效果高度依賴輸入的背景詳細程度，背景太簡短時準確度會明顯下降。

4. **新發現——完全測不到「考驗有沒有做功課」型的題目**：#10（飯店前台）的「你覺得這家飯店缺點是什麼」、#4（HR）的「公司可以怎麼吸引應徵者」，這類要求候選人對「這家公司/這個產業」有主動研究的題目，這版 prompt 一次都沒猜到——因為這類題不是從候選人背景或 JD 的「缺口」推論出來的，而是需要額外的公司/產業外部資訊，這版 prompt 完全沒有這個輸入來源。**如果要補強，下一版應該加入「查一下這家公司/產業」這個步驟**，而不是只看背景與 JD。

## 行動推薦有沒有人照做

10 篇都是語料，不是真人訪談，這一項還是沒有資料。`validation-plan.md` 這部分要真實面試者質性訪談才能驗證，不是跑語料能回答的——這次 demo 裡加的「已準備／有幫助」勾選框，是量測介面的示範，不是真實資料。
