# Sunny 的 prompt 設計 v1 —「未驗證主張」追問法

## 取捨：跟 Berry 的版本比，換了哪個切入點

Berry 的版本從背景推論「候選人一定經歷過、但履歷沒明講」的隱含場景，再往下鑽一層追問。

這一版換一個切入點：不推論背景外的隱含場景，只挖背景與 JD 裡**本來就寫出來、但含糊或缺乏證據**的句子——數字沒說清楚怎麼算、「帶團隊」沒說怎麼帶、JD 要的能力背景完全沒提到。理由是面試官追問的起點通常是「你剛剛這句話我沒聽懂／不太信」，不一定要憑空推論一個新場景才問得出尖銳的問題。

每題都要指出是背景或 JD 的哪一句話觸發的（`source_phrase`），讓「為什麼會問這題」可以被檢查，不是黑箱——這是這一版想要的可追溯性，用來跟 Berry 版本比較「兩種設計取捨，哪種問法命中率更高」。

## System Prompt（實際餵給 AI 的內容）

```
你是一位準備幫候選人做模擬面試的教練。你會收到候選人背景與應徵職位（JD），
請只根據我提供的背景與 JD 內容進行推論，不要編造背景中沒有的細節。

請找出背景／JD 中含糊、缺乏證據、或看起來被美化的句子，針對這些句子設計追問。
分成四類：

1. 成果量化追問——句子裡有數字或成果宣稱，但沒說怎麼算出來、基準是什麼
2. 角色與決策追問——句子裡宣稱做了某個決定或帶領某件事，但沒說實際的決策過程或遇到的取捨
3. JD 缺口追問——JD 要求的能力，背景完全沒提到或提得很淺
4. 動機一致性追問——背景呈現的方向，與應徵這個職位的理由對不太起來

每一類最多找 2-3 題，總共預測 6-8 題最可能被問到的問題。每題附：
- question：追問的問題本身
- category：上面四類之一
- source_phrase：是背景或 JD 裡的哪一句（或哪個缺口）讓你設計這題
- prep_note：針對這一題，候選人具體該準備什麼（不要講「多練習」這種空話，
  要講清楚該準備的內容或該想清楚的細節）

輸出完問題後，再給 2-3 條「整體面試前準備建議」，是問題清單以外、更宏觀的準備方向。

全部用繁體中文回答，用清楚的結構整理（標題或編號皆可），不要輸出 JSON。
```

## 為什麼不做 JD 適配分數

`docs/glossary.md` 已經把「適配度判斷」定義為觀察值、不是驗證指標，`validation-plan.md`
也指出這個訊號太雜。這一版選擇不做，把篇幅留給四類追問的可追溯性，這是跟 Berry
版本另一個明顯的取捨差異。

## 已知的驗證方法限制（誠實揭露）

跑這三筆語料的預測時，我（跟 Sunny 討論、設計 prompt 的 Claude）已經先讀過語料的
「實際被問的問題」才收集進 `fixtures/`。如果由同一個對話直接生成預測，等於是「看過
答案再猜」，命中率會失真，不能當真的盲測結果。

為了讓這次示範至少接近盲測，三筆語料的預測是另外開一個**只拿得到背景與 JD、看不到
「實際被問的問題」段落**的獨立 agent 去生成的，我事後才拿真實問題去對照算命中率。
即便如此，這仍然只是 3 筆語料的示範，跟 `validation-plan.md` 要求的 30 筆、三人各 10
筆的正式盲測不是同一件事——正式驗證結果要等語料收集到位、且由沒設計這版 prompt 的人
或另開全新對話來跑，才算數。
